# Контекстная схема

Рядом с [проектным документом](project-description.md).
Снаружи известна преподавательская платформа. Канал обмена — брокер сообщений, продукт на схеме не назван. Устройство платформы сюда не входит.

Контур `quiet-water` показан целиком: один процесс, без своей страницы. Портфель открывают на платформе. Окно свечей лежит в памяти этого процесса и пропадает при остановке. Слои внутри процесса — на [схеме компонентов](component-diagram.md).

```mermaid
flowchart TB
  subgraph users ["Пользователи"]
    direction LR
    student["Студент-разработчик и оператор<br/>Щербак Руслан, llnightll, МПБ-401"]
    teacher["Преподаватель<br/>Заказчик"]
  end

  subgraph external ["Внешняя система"]
    direction TB
    platform["Преподавательская платформа"]
    broker["Брокер сообщений"]
    platform ~~~ broker
  end

  teacher -->|"прогоны, задания, портфель"| platform

  subgraph app ["Контур сервиса quiet-water"]
    direction LR

    subgraph adapters ["Адаптеры"]
      direction TB
      env["Конфигурация окружения"]
      client["Клиент брокера: чтение и запись"]
      memory["Окно свечей в памяти"]
    end

    subgraph scenarios ["Сценарии"]
      direction TB
      registration["Регистрация сервиса"]
      candle["Решение по закрытой свече"]
      health["Сводка health"]
    end

    subgraph core ["Домен"]
      policy["Walk-forward и RSI"]
    end

    subgraph http ["HTTP"]
      route["GET /health"]
    end
  end

  student -->|"запуск, .env, журнал, Docker"| env
  broker -->|"свечи и ответ регистрации"| client
  client -->|"запрос регистрации и рекомендация"| broker
  env -->|"адрес, топик, group.id, пороги"| client
  env -->|"имя и версия сервиса"| health
  client --> registration
  registration -->|"можно ли публиковать"| candle
  client --> candle
  candle --> memory
  candle --> policy
  policy -->|"BUY / SELL / HOLD"| candle
  health --> route
```

| Часть | Ответственность |
|---|---|
| Конфигурация окружения | Адрес брокера, топик, свой `group.id`, пороги стратегии. Секретов в репозитории нет |
| Клиент брокера | Подписка на `market.candle.closed`, запрос регистрации, публикация рекомендации. Обрыв брокера не останавливает процесс |
| Регистрация | Ждёт `account.registration.accepted`. При отказе фиксирует причину и запрещает публикацию |
| Окно в памяти | Короткая история свечей по тикеру. Отдельной базы нет |
| Walk-forward и RSI | Фаза и сигнал. Не знает ни про HTTP, ни про брокер |
| GET /health | Отдаёт `status`, `service`, `version`, `components` без авторизации |

| Часть | Есть в приложении | Как участвует |
|---|---|---|
| Фронтенд | нет | Своей страницы сервис не отдаёт. Проверка живости идёт на `GET /health`, портфель открывают на платформе |
| Бэкенд | да | Единственный процесс: адаптеры, сценарии, домен и HTTP |
| База данных | нет | Окно свечей хранит сам процесс в памяти |
| Платформа и брокер | снаружи | Платформа ведёт прогон и портфель. Брокер доставляет регистрацию, свечи и рекомендацию |
