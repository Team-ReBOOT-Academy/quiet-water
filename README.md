# Quiet Water (`quiet-water`)

Студенческий **strategy-service** для преподавательской платформы ОмГУ
([Teacher Trading Platform](https://omsu.7bits.it/)).

Сервис не торгует на реальной бирже и не считает виртуальный портфель.
Он стоит снаружи платформы: на каждую закрытую свечу отвечает одним
решением `BUY` / `SELL` / `HOLD` и отдаёт диагностику `GET /health`.

Автор: **llnightll**  
Проектный документ: [project-description.md](project-description.md)  
Идентификатор сервиса / будущий `strategyId`: `quiet-water`

## Предварительно выбранная стратегия

**Walk-forward «пропускной балл»** (quiet water — сначала тишина, потом удар):

1. Первые `N` свечей по каждому тикеру — набор окна, наружу только `HOLD`.
2. Следующие `K` свечей — экзамен уже посчитанной формулы успеха, снова только `HOLD`.
3. Если hit-rate на экзамене не ниже порога `T`, сервис начинает торги.
4. Дальше окно скользит на одну свечу, формула успеха пересчитывается.
5. Сетап входа — разворот RSI(14) из зон 30/70; торговать разрешает только `successRate`.

Языковая модель в контур `BUY`/`SELL` не входит. Это опциональная «звезда»
после отправки рекомендации, см. проектный документ. В задании 1 не реализуется.

Стартовые пороги (из окружения, не из кода): `N=90`, `K=45`, `M=10`, `W=20`, `T=0.55`.

## Требования к окружению

Собрать и запустить **без IDE** можно двумя способами: Gradle Wrapper или Docker.
На машине достаточно одного из вариантов.

**Вариант A — локальная JVM**

- JDK **24** (тем же major, что в образе)
- доступ в сеть при первом `./gradlew` (wrapper качает дистрибутив Gradle сам)
- `curl` для проверки `/health`

**Вариант B — только Docker**

- Docker Engine 24+
- JDK на хосте не нужен

Секреты Kafka и `secretKey` преподаватель выдаёт отдельно. В Git их нет.
Образец имён переменных — `.env.example` (появится вместе с каркасом).
Пока брокер не выдан, сервис должен подниматься в статусе `DEGRADED`.

## Команды сборки и запуска без среды разработки

Команды ниже — контракт запуска каркаса на Kotlin/Ktor. Их же нужно
повторить в CI или на машине преподавателя.

### Gradle Wrapper

```bash
chmod +x ./gradlew
./gradlew test
./gradlew run
```

В другом терминале:

```bash
curl -s http://127.0.0.1:8888/health
```

Ожидаемый ответ живого каркаса (задание 1, Kafka ещё не подключена):

```json
{
  "status": "DEGRADED",
  "service": "quiet-water",
  "version": "1.0.0",
  "components": {
    "kafka": {
      "status": "DOWN",
      "details": "broker is not configured"
    }
  }
}
```

Код ответа HTTP — **200**, даже если `status` равен `DEGRADED`.
Авторизация на `/health` не нужна.

Остановка локального процесса: `Ctrl+C`. Приложение должно закрыть
HTTP-сервер и выйти с кодом 0.

Собрать дистрибутив без IDE:

```bash
./gradlew installDist
./build/install/quiet-water/bin/quiet-water
```

### Docker (предпочтительный способ «без среды разработки»)

```bash
docker build -t quiet-water:1.0.0 .
docker run --rm -p 8888:8888 --name quiet-water quiet-water:1.0.0
```

Проверка и остановка:

```bash
curl -s http://127.0.0.1:8888/health
docker stop quiet-water
```

Переменные окружения передавать через `--env` / `--env-file`, не запекать
в образ. Пароли и ключи в репозиторий не класть.

Контейнер должен корректно завершаться по `SIGTERM` (`docker stop`).

## Что сознательно не входит в этот репозиторий

- UI — наблюдение портфелей уже есть на платформе
- собственная база — появится только в задании про persistence
- клиент Kafka — следующее открытое задание (`semester-1-broker`)
- реальные заявки брокеру — платформа их не отправляет
